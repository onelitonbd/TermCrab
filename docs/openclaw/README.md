# OpenClaw, studied page by page — and where TermCrab stands

This directory is the answer to two questions that used to live in the owner's head:

1. **What exactly is on docs.openclaw.ai?** → every documented page gets its own section, generated from OpenClaw's own `docs/` tree, with a one-line summary, a heading outline and a TermCrab relevance verdict.
1. **How do we actually beat OpenClaw, and in what order do we build?** → [BEAT-PLAN.md](BEAT-PLAN.md) — smallest to biggest, every claim cited, plus the kill list.
2. **Where is TermCrab right now, and how much work is left?** → [TRACKER.md](TRACKER.md), measured from TermCrab's source by `scripts/census.mjs` — 150 capabilities, each with a machine probe that re-verifies it.

Neither answer is written from memory. Both are regenerated by scripts in `scripts/`.

## How it was made (and how to redo it)

**Source of truth for the site.** The website is generated from OpenClaw's `docs/` tree, so the catalogue is built from that tree rather than scraped HTML — same content, exact routes, no rendering guesses. Spot-checked live on 2026-10-03: `/concepts/queue` served from [docs.openclaw.ai](https://docs.openclaw.ai/concepts/queue) matches `docs/concepts/queue.md` in the source tree.

```bash
# 1. get the docs tree (no build, no deps, ~30 MB)
git clone --filter=blob:none --no-checkout --depth 1 \
  https://github.com/openclaw/openclaw.git .cache/openclaw
git -C .cache/openclaw sparse-checkout set docs && git -C .cache/openclaw checkout

# 2. (re)generate the catalogue — 1,335 sections + the site map + catalog.json
node scripts/openclaw-docs-report.mjs --docs .cache/openclaw/docs

# 3. measure TermCrab itself, and refresh the tracker's generated block
node scripts/census.mjs                 # human-readable summary + drift report
node scripts/census.mjs --json          # machine-readable
node scripts/census.mjs --write         # also writes data/census.json + TRACKER.md block
node scripts/census.mjs --area gateway  # one area only
```

Both scripts take their inputs from the working tree, so a run after any code change gives you a diffable answer instead of an opinion.

## The three rules that keep this honest

1. **A capability is not done until it has a probe.** If you cannot write a grep that proves it is wired, it is not wired. This rule alone would have caught all ten broken rows of the first measurement — all ten are fixed now, and the list is empty in [TRACKER.md](TRACKER.md) §3.
2. **Never edit the generated blocks by hand** — `sections/`, `00-SITE-MAP.md`, `data/`, and the measured block in `TRACKER.md` all come from the scripts. Hand-written judgement lives in `analysis/`, `TRACKER.md` §3–6 and `ROADMAP.md`.
3. **Drift is the feature.** When the census prints `DRIFT`, code has moved under a recorded judgement. Re-read the row, re-judge it, two minutes, every time. That is the difference between this tracker and `docs/ARCHITECTURE.md` — which described files that never existed and helped nobody.

## What shipped since the study (batches 11–13, 2026-10-03)

This study was written before the fixes; the tracker is the live document, and
[WORKLOG.md](../../WORKLOG.md) is the batch-by-batch record. In short:

| Study finding | What shipped |
|---|---|
| `LLM summarisation for compaction` — ABSENT | **WORKING**: `SessionStore.compactWithModel()` writes a model digest in bounded chunks, records who wrote it and what it covers, and falls back to the extractive digest with a reason (batch 11) |
| `Docs that match the code` — PARTIAL | **WORKING**: the file map is generated by `scripts/docs-map.mjs` and `--check` runs inside the suite (batch 11) |
| Phone claims without numbers | **Measured**: `scripts/bench.mjs` (install · cold start · idle RSS · restart · one offline turn) feeds the README block; a test fails if the numbers drift (batch 12) |
| Offline outbox (BETTER, untested) | **Exactly-once tested**, with the guarantee stated honestly (batch 12) |
| Five channel adapters with no tests | **WORKING + tested**: Discord, Slack, Signal, SMS and Matrix route to the agent and queue failed sends; the SDK/daemon stays optional (batch 13) |
| Typing indicators · Per-command help · Shell completion · Colour discipline — all ABSENT | **WORKING**, each with a test (batch 13) |
| `JSON output mode` — PARTIAL (`doctor --json` only) | **WORKING**: one envelope for 11 commands, failure included, logs moved to stderr; the contract is written down in `docs/CLI.md` (batch 14) |
| `File operations` · `Disk budget` (hardened) | **the agent's own inbox**: arrivals are indexed and their text saved beside them, so it can list, re-read and explain a trimmed file — and the channel table in the docs is cross-checked against the code by a test (batch 17) |
| `Document extraction` — ABSENT | **WORKING**: our own zero-dependency readers take the text out of an arriving PDF (content streams + FlateDecode), DOCX/PPTX/XLSX (small ZIP reader on `node:zlib`) and every text format, capped with a truncation note; a scanned PDF is refused with an OCR sentence. A picture is described by a model that can see (real `image_url` part) or the agent is told plainly that it cannot see it (batch 16) |
| `Media send/receive` · `Group / ambient events` · `Slash commands in chat` | **WORKING / PARTIAL / WORKING**: Telegram files in *and* out (inbox, `send_file`, executables refused), group messages only when addressed, and `/usage` `/sessions` `/memory` `/help` in the chat — rules in `docs/CHANNELS.md` (batch 15) |
