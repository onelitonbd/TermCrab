## 4. Area by area — the honest version

Score is the census score for that area. "Their pages" is how many pages docs.openclaw.ai spends on it — a decent proxy for how seriously they treat it.

### gateway — 35% · their pages: 160
**Real:** a working HTTP+SSE gateway on :7788 with 77 route handlers, a health endpoint, a bind-time guard that refuses non-loopback without a token, canvas widgets, an event bus.
**Fake:** the auth module. `checkToken` is written, exported, tested — and imported by nothing. Every `/api/*` route is open, and the webhooks route says so in a comment. The documented Token is decoration.
**The move:** wire `checkToken` into one place (the `/api/` prefix check at `server.ts:712`) and gate the webhook branch. Half a day, and it converts "a phone port open on your LAN" into a defensible product.

### agent — 53% · their pages: 79 concepts + 1 architecture page
**Real:** streaming deltas, tool round-trips, a failover chain with cooldowns, thinking levels, a repetition detector, subagent spawn/wait tools, progress cards. This is the area where the code is closest to the docs.
**Fake:** serialization and steering. The queue is a well-written object nobody drains, and `skipQueue: true` is passed from the server path — so the default deployment is the un-serialized one.
**The move:** drain the queue (one `for(;;)` loop per session), then make `queueMode` actually branch. Everything OpenClaw documents about queue behaviour is a consequence of those two functions.

### sessions — 29% · their pages: 79
**Real:** JSONL transcripts, a sessions CLI (`ls/export/rename/purge`), session tools the agent itself can call (`sessions_list/history/search/send`), manual `/new`.
**Fake:** nothing here is fake; it is just narrow. No write fencing, no reset policies (`idle`/`daily`), no `dmScope`, no cross-channel identity linking, and five unrelated session silos (`web:main`, `telegram:*`, `cron:*`, `heartbeat`, `dream`) instead of one main session.
**The move:** the five silos are the real bug — it is why "what did I tell it yesterday?" has no answer. One `agent:<id>:main` key with routed background results, then lifecycle policies.

### context — 23% — the worst area, and the one that decides whether this is an agent
**Real:** `MEMORY.md` + daily logs + compacted digests, optional local embeddings, dreaming (idle-time consolidation) — genuinely ahead of most small agents.
**Fake:** compaction and memory injection. Both look implemented and both lose data by construction (#5 and #6 above).
**The move:** stop calling it compaction until it summarises. Make the prompt read a *budgeted tail* + a search-selected slice instead of `readHead`. Two days for both, and it fixes the number one user-visible complaint ("it forgets").

### tools — 56% · their pages: 117
**Real:** ~54 tools, root-bounded file access, `exec` behind a config flag, MCP client wired at `server.ts:345`, CDP browser, Node-`vm` code execution, and 15 Termux:API phone tools nobody else has.
**Fake:** nothing fake — but `ask_user` has no terminal renderer, and the browser tool needs a system Chrome that Termux users usually do not have.
**The move:** the phone tools are the moat. Make them first-class in the docs and in the prompt, and make `ask_user` work in the CLI.

### skills — 56% · their pages: 337 (incl. 163 plugin reference pages)
**Real:** SKILL.md loading with progressive disclosure, user overrides, import from OpenClaw, agent-authored skills via `skill_workshop`, 5 bundled skills.

## 5. Why the totals look like that

- **You are comparing a 2-month, 1-person, 15k-line project against a 390k-star, 2,000-contributor, 421MB-of-TypeScript foundation project.** A 41% score against *that* list is not a bad score; it is an unreasonable denominator. The number that matters is: **how many of your 150 capabilities are broken (7) and how many of the remaining 45 absent ones are actually needed to win on a phone (about 20).**
- **Where the effort isn't:** 164 of the 482 remaining days sit in the `later` lane, and roughly a third of that is a native companion app (20 days alone) and a plugin registry you deliberately do not want.
- **Where the effort is:** ~40 days of core work fixes the seven broken rows. That is the difference between "an agent that sometimes forgets and can be driven by anything on the LAN" and "an agent you can trust with a real task".
- **The parity line that is actually reachable:** ~320 days (core + parity) with disciplined work. Part-time, that is about a year. Full-time, about 7–8 months. Everything past that is cloning their ecosystem, which is neither possible alone nor useful.

## 6. How to keep this honest

Rot is the enemy. `docs/ARCHITECTURE.md` is proof: it described a system that never existed, and you were tracking it in your head.

The protocol, in order:

1. **Never edit this file's measured block by hand.** `node scripts/census.mjs --write` regenerates it.
2. **After every code change**, run `node scripts/census.mjs`. If it prints `DRIFT`, the code moved out from under a judgement — open this file, re-read that row, and change the verdict. Drift is not an error; it is the reminder.
3. **A new capability is not done until it has a probe.** If you can't write a grep/pattern that proves it is wired, it is not wired. That single rule would have caught all ten broken rows of the first measurement (three are already fixed).
4. **Refresh the OpenClaw side monthly:** `git -C .cache/openclaw pull && node scripts/openclaw-docs-report.mjs --docs .cache/openclaw/docs`. The catalogue diff tells you what they shipped while you worked.
5. **Update the ROADMAP when a lane moves.** The 43/282/164 split is the closest thing this project has to a project plan; keep it current, not decorative.
