# v0.5 Scope — "Works Everywhere"

> Status: **proposed scope (not started)**. Written 2026-09-29 on top of v0.4.0.
> Goal: turn a launched project into a *retained* project — remove every reason a
> curious visitor bounces after `git clone`, and every reason a daily user churns
> after week one.

## Theme

v0.4 made TermCrab *smarter* (tiers, dreaming, embeddings, wake). v0.5 makes it
**shareable and forgettable-in-a-good-way**: a stranger installs it in 5 minutes
without reading source, an OpenClaw user migrates without losing work, and a
long-term user updates without thinking.

## Explicitly OUT of scope (v1.0+ unless forced)

- npm publish, F-Droid wrapper APK, website/docs site (v1.0 "Publish")
- Plugin/extension SDK (v1.0)
- CrabCloud relay/tunnel service (monetization track — guide in #9 is the free stopgap)
- Signal/LINE/Teams channels beyond the spikes above
- Changing the zero-runtime-deps contract (extensions stay opt-in forever)

## Test & release plan (same discipline as v0.1–v0.4)

1. `tsc` strict clean; every P0 item ships with unit tests (target: +10–15 tests).
2. Smoke: update (against real GitHub release API), doctor --share redaction proof,
   import fixture round-trip, install.sh dry run.
3. Docs: README/CHANGELOG/PRODUCT updated; version bump minor → **0.5.0**,
   tag + GitHub release, push to `arena/01a0ec99-claw` only (no PRs/merges).
4. Definition of done per item: code + tests + docs line + smoke evidence.

## Suggested build order

Sprint A: #1, #2, #4 (all small/medium, high leverage for launch traffic)
Sprint B: #3 (largest — migration story), then #7, #8
Sprint C: #5, #6, #9; spikes #10–#13 whenever waiting on reviews/builds

## Risks

| Risk | Mitigation |
|---|---|
| Launch traffic arrives before #1/#4 | Posts go out with install section tested by checklist in `docs/LAUNCH.md` §4 |
| `import openclaw` schema drift | Pin to OpenClaw's documented layout; `--dry-run` default in doubt; unmapped keys reported, never guessed |
| Wake-word spike eats time | Hard 2-day cap, battery threshold decides, P2 by definition |
| Single maintainer bandwidth | P0 order is deliberately "smallest first"; P2 can all be cut without re-scoping |
