## 2. Now — batch 31, finished: storage you can move between phones (this commit)

A phone is a device you drop in water, lose in a rickshaw or replace when the screen cracks. Until
now everything the agent knew lived in one directory with no version and no way out. This batch
gives the *state* a version, gives the whole home a door, and gives a bad update a way back.

**Limits stated in the open:** the archive is uncompressed (a phone has little to spare, and `tar -xzf`
elsewhere still reads it after one `gzip`), it is not encrypted — the config holds an API key, so a
backup file is as sensitive as the phone; migrations exist for the three shapes that actually changed
in this project's history, not for a decade of releases; and a rollback restores *files*, not a running
process — a session in flight is still in flight.

## 6. Rules this file follows (so it stays honest)

1. **No test, no "done".** A step moves to ✔ only with a named test that fails without the change.
2. **No date promises.** Sizes are in focused days; order is fixed, calendar is not.
3. **Stale is loud.** `status.mjs` reports how many commits landed since this file was last updated. Zero is the only healthy number: it prints `STALE` and exits non-zero otherwise, and `test/worklog.test.ts` asserts it — so a commit that skips the tracker fails the suite.
4. **One screen.** If this file grows past a screen of current work, the history moves to §4 and §2 stays small.
5. **Every commit touches this file.** Either it updates §2 (the batch moved) or §4 (a batch shipped). That is what keeps the count at zero without remembering to do it.
